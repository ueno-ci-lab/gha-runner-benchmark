### 分かったこと

- キャッシュの効果が大きい。ビルドは 131 秒 → 19 秒、全体は 204 秒 → 82 秒（約 6 割短縮）
- チェック系ジョブの時間はほぼ Docker イメージの準備（キャッシュからの復元と読み込み）。コマンド自体は 1〜4 秒
- そのため、今の構成での Blacksmith との比較は「キャッシュの復元とイメージ読み込みの速さ」が中心になる
- 待ち時間は 3〜4 秒でほぼない
- ばらつきは小さい（全体の中央値と p90 の差は 3〜14 秒）

## 比較：Blacksmith を使う / 使わない（2vCPU）

| 条件 | ランナー | 全体（中央値） | ビルド | 課金対象 | 1 回あたりのコスト |
|---|---|---|---|---|---|
| コールド | GitHub 標準 | 204 秒 | 131 秒 | 6.5 分 | 約 $0.039 |
| コールド | Blacksmith | **108 秒（約 47% 短縮）** | 61 秒 | 4.5 分 | **約 $0.018（約 54% 削減）** |
| ウォーム | GitHub 標準 | 82 秒 | 19 秒 | 4 分 | 約 $0.024 |
| ウォーム | Blacksmith | **63 秒（約 23% 短縮）** | 19 秒 | 4 分 | **約 $0.016（約 33% 削減）** |

単価は GitHub 標準 $0.006/分、Blacksmith $0.004/分（2vCPU）。どちらもジョブごとに分単位で切り上げて計算している。

### 分かったこと

- **コールドでは Blacksmith が約半分の時間**。ビルドが 131 秒 → 61 秒と大きく短縮した
- **ウォームではビルド時間は同じ（19 秒）**。差が出たのはチェック系ジョブのイメージの準備で、42〜45 秒 → 16〜17 秒。Blacksmith のビルダーとキャッシュ（同じ基盤上のレイヤーキャッシュ）からイメージを読み込むほうが、GitHub の gha キャッシュから復元するより速い
- **コストは 33〜54% 安い**。単価が安いことに加え、コールドでは課金対象の分数も減る
- **待ち時間だけは GitHub 標準が短い**（3〜4 秒 → 約 9 秒）。ただし全体の差に比べれば小さい
- コマンド自体（1〜4 秒）はどちらもほぼ同じで、今の構成では CPU 性能の差はほとんど出ていない
- 計測は 1 日分のみで、時間帯や曜日による変動は確認していない
