# トラブルシュート

## Laravel のプロジェクト作成後にファイルが消えた

- **症状**：コンテナ内で `composer create-project` を実行したが、プロジェクトが残らなかった
- **原因**：作成先をコンテナ内の `/tmp` にしていたため、`--rm` でコンテナが終了した時点で消えた
- **対処**：マウントしているディレクトリ配下に作成し、プロジェクトのルートに移動した

## PHPStan で Mockery の型エラー

- **症状**：`Property ... (TaskRepositoryInterface&MockInterface) does not accept Mockery\MockInterface.`
- **原因**：`Mockery::mock()` の戻り値の型が `MockInterface` としか推論されない
- **対処**：一度変数に受け、`/** @var TaskRepositoryInterface&MockInterface $repository */` で型を明示してから代入した

## Pint で使っていない import を検出

- **症状**：`pint --test` で `no_unused_imports` が出た
- **対処**：`vendor/bin/pint` を実行して自動修正した

## actionlint が動かない

- **症状**：`no project was found in any parent directories`
- **原因**：git リポジトリになっていなかった
- **対処**：`git init` してから実行した

## MySQL が起動しない（ポートの衝突）

- **症状**：`Bind for :::3306 failed: port is already allocated`
- **原因**：別プロジェクトの MySQL コンテナ（`stf_dbm`）が 3306 番を使っていた
- **対処**：このプロジェクトの MySQL は 3316 番で公開するように変更した。`FORWARD_DB_PORT` で番号を変えられる（アプリの 8000 番も `APP_PORT` で変更可）

## マイグレーションで接続拒否

- **症状**：`SQLSTATE[HY000] [2002] Connection refused`
- **原因**：MySQL の初回起動が終わる前にアプリが接続しにいった
- **対処**：`compose.yaml` で MySQL に healthcheck を設定し、app は `condition: service_healthy` で待つようにした。起動は `docker compose up -d --wait` を使う

## Laravel のひな形に含まれる CLAUDE.md / AGENTS.md

- **内容**：ホストに PHP をインストールし、Laravel Boost を導入するよう指示する内容だった
- **対応**：Docker で動かす方針と合わないため従わなかった。ファイルを残すか削除するかは未定

## ホストの Node が古い

- **内容**：ホストの Node は 18 で、最近の Vite（Node 20 以上が必要）には古い
- **対応**：動作確認画面を Vite を使わない作りにしたため、現状は影響なし
