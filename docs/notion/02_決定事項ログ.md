# 決定事項ログ

| 日付 | 決めたこと | 理由 | ほかの選択肢 |
|---|---|---|---|
| 2026-10-10 | Laravel は最新版（13 系）を使う | 検証結果を今後の新規開発にそのまま活かすため | 既存プロジェクトと同じバージョン |
| 2026-10-10 | ローカル開発環境は Docker（Docker Compose） | ホスト環境に依存せず、CI とバージョンを揃えるため | ホストに PHP を直接インストール |
| 2026-10-10 | Sail ではなく自前の Dockerfile を使う | 開発用と CI 用を 1 つの Dockerfile で管理し、バージョンを確実に揃えるため | Laravel Sail |
| 2026-10-10 | PHP は 8.5 | Laravel 13 の要件（8.3 以上）を満たす最新版のため | 8.3 / 8.4 |
| 2026-10-10 | リポジトリは private | 実運用に近い条件で比較するため | public（GitHub 標準ランナーが 4vCPU になる） |
| 2026-10-10 | 比較は 2vCPU 同士 | private リポジトリの GitHub 標準ランナーが 2vCPU のため | 4vCPU 同士 |
| 2026-10-10 | テストは PHPUnit | チームで使い慣れているため | Pest |
| 2026-10-10 | CI でも Docker を使い、コンテナ内でチェックを実行する | ローカルと CI で PHP や拡張のバージョンを揃えるため。Docker ビルドとキャッシュの比較もできる | `setup-php` で PHP を直接インストール（速いがバージョンを別管理） |
| 2026-10-10 | テストの DB アクセスはモックにする | CI で MySQL を起動しなくて済み、テストが速く安定するため | テスト用 MySQL、SQLite インメモリ |
| 2026-10-10 | テスト中に SQL が発行されたら失敗させる | モック漏れを確実に検出するため | 特に制限しない |
| 2026-10-10 | 静的解析は Larastan のレベル 8 | 新規プロジェクトで最初から厳しめにしておくため | レベル 5〜6 から段階的に上げる |
| 2026-10-10 | 動作確認用の GUI は Blade と素の JavaScript で作る | Node や Vite が不要で、Docker 構成と CI に影響しないため | Vue / React（ビルドが必要） |
| 2026-10-10 | Laravel のひな形に含まれる CLAUDE.md / AGENTS.md の指示（ホストへの PHP インストール、Laravel Boost の導入）には従わない | Docker で動かす方針と合わないため | 指示どおり導入する |
