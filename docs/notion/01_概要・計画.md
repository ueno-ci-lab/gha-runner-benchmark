# 概要・計画

## 目的

- GitHub Actions で Laravel の CI（テスト・静的解析）を構築・運用する手順を検証する
- ランナー環境として GitHub 標準ランナーと Blacksmith（https://www.blacksmith.sh/）を比較し、採用可否を判断する材料を得る

## 比較条件

- 同じコミット・同じワークフローを、ランナーだけ変えて同時に実行する
- リポジトリは private のため、GitHub 標準ランナーは 2vCPU。Blacksmith も 2vCPU（`blacksmith-2vcpu-ubuntu-2404`）に揃える
  - 補足：GitHub 標準ランナーは public リポジトリだと 4vCPU になるため、vCPU 数を揃えないと公平な比較にならない
- 各パターンを 10 回以上実行し、中央値と p90 で比較する
- キャッシュなし（コールド）とキャッシュあり（ウォーム）の両方を計測する

## Blacksmith の前提（2026-10-10 時点の公式情報）

- GitHub Organization のリポジトリでのみ利用可能（個人リポジトリは不可）
- 導入は GitHub App のインストールと `runs-on` の書き換えのみ
- 無料枠：月 3,000 分
- 料金：Linux x64 は $0.004/分（公式表記では GitHub より 1 分あたり 33% 安い）。vCPU サイズ別の単価は要確認
- `actions/cache` は変更なしで動作。キャッシュ容量は 1 リポジトリあたり週 25GB
- Docker レイヤーキャッシュは専用 Action（`useblacksmith/setup-docker-builder`、`useblacksmith/build-push-action`）への差し替えが必要

## 評価項目

| 項目 | 内容 |
|---|---|
| 速度 | ワークフロー全体、ジョブ別、ステップ別の所要時間 |
| 待ち時間 | ジョブが開始されるまでの時間 |
| コスト | 1 回あたりの実行分数 × 単価、月間の想定実行回数での試算 |
| 安定性 | 失敗率、実行時間のばらつき |
| 運用性 | 移行の手間、ダッシュボード、ログ検索、SSH デバッグなど |
