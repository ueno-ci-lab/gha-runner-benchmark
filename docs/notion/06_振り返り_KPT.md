# 振り返り（KPT）

> 2026-10-10 時点の暫定版。Phase 4・5 が終わったら更新する。

## Keep（良かった点・続けること）

- 開発用と CI 用を 1 つの Dockerfile で管理し、PHP のバージョンを確実に揃えられた
- リポジトリをインターフェース化したことで、DB をモックにしたテストが書きやすかった
- テスト中に SQL が発行されたら失敗させるガードを入れ、モック漏れを確実に検出できるようにした
- ワークフローを再利用型にしたことで、ランナーだけを変えて同じ処理を比較できる
- 画面の動作確認をヘッドレスブラウザで自動化し、JavaScript のエラーがないことまで確認した
- 決定事項を理由とセットで残した

## Problem（課題・困ったこと）

- 別プロジェクトの MySQL とポートが衝突した（ローカル環境の使用ポートを事前に確認していなかった）
- MySQL の起動待ちを考慮しておらず、初回のマイグレーションが失敗した
- テストは DB をモックにしているため、Eloquent での実装（実際の SQL）は自動テストで確認できていない
- テストが 1 秒未満で終わるため、ランナーの CPU 性能の差が CI 時間に出にくい
- GitHub 上ではまだ CI を一度も動かしていない

## Try（次に試すこと）

- Phase 1 を完了させ、GitHub 上で CI を動かす
- 実行時間を自動で集計するスクリプトを作る（gh CLI と GitHub API）
- CPU 性能の差を見たい場合は、テストの件数や処理の重さを増やす
- Eloquent での実装を確認する結合テストを、モックのテストとは別に用意するか検討する
- Compose の初期設定として、ポートの変更と MySQL の起動待ちを最初から入れておく
